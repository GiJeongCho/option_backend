# 서버 실행 가이드 (외부 공유용)

모든 게 꺼져 있는 상태에서 처음부터 켜서 **다른 사람이 인터넷으로 접속**할 수 있게 하는 순서다.

구성 요약:

- **백엔드**: FastAPI, 포트 `8000` (데이터 API `/api/...` 제공)
- **프론트엔드**: Vite 개발 서버, 포트 `5173` (`/api` 요청을 백엔드로 프록시)
- **터널**: cloudflared, `5173`을 인터넷 공개 주소로 노출
- 브라우저는 `5173`만 바라보고 `/api`는 Vite가 내부에서 `8000`으로 넘겨준다. 그래서 **터널은 5173 하나만 열면 된다.**

> 터미널 3개를 각각 열어두고, 세 개 모두 켜져 있는 동안에만 외부 접속이 유지된다.

---

## 1단계. 백엔드 실행 (터미널 1)

```powershell
cd C:\project\option\backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

- `INFO: Application startup complete.` 가 뜨면 정상.
- 코드 수정 중 자동 반영이 필요하면 뒤에 `--reload` 를 붙인다.
- 이 창은 켜둔 채로 둔다.

확인(선택): 브라우저에서 `http://127.0.0.1:8000/api/health` → `{"status":"ok", ...}` 가 나오면 OK.

---

## 2단계. 프론트엔드 실행 (터미널 2)

```powershell
cd C:\project\option\frontend
npm run dev
```

- `VITE vX.X.X ready` 와 `Local: http://127.0.0.1:5173/` 가 뜨면 정상.
- 이 창도 켜둔 채로 둔다.
- (최초 1회만) 의존성이 없다면 먼저 `npm install` 을 실행한다.

확인(선택): 브라우저에서 `http://127.0.0.1:5173/` 접속 → 화면이 뜨면 OK.

---

## 3단계. 인터넷 터널 실행 (터미널 3)

```powershell
cloudflared tunnel --url http://localhost:5173
```

- 실행하면 출력 중간에 아래처럼 **공개 주소**가 나온다:

  ```
  +----------------------------------------------------------+
  |  Your quick Tunnel has been created! Visit it at ...      |
  |  https://랜덤이름.trycloudflare.com                        |
  +----------------------------------------------------------+
  ```

- 이 `https://....trycloudflare.com` 주소를 상대에게 전달하면 접속된다.
- 이 창도 켜둔 채로 둔다.

---

## 접속 / 공유

- 상대는 3단계에서 나온 **`https://....trycloudflare.com`** 주소로 접속한다.
- `/api` 데이터도 이 주소를 통해 자동으로 동작한다 (별도 설정 불필요).

---

## 끄는 방법

각 터미널에서 `Ctrl + C` 를 누르거나 창을 닫는다. 세 개 다 끄면 외부 접속이 끊긴다.
(순서 무관. 보통 터널 → 프론트 → 백엔드 순으로 끈다.)

---

## 자주 겪는 문제

- **접속 시 403 `Blocked request. This host is not allowed.`**
  - Vite가 외부 도메인을 막은 경우다. `frontend/vite.config.ts` 의 `server.allowedHosts` 에 `'.trycloudflare.com'` 이 있는지 확인한다. (이미 설정해 둠)
  - 설정을 고쳤으면 Vite가 자동 재시작될 때까지 기다렸다가 다시 접속한다.
- **터널을 다시 켜면 주소가 매번 바뀐다.**
  - 무료 quick 터널의 특성이다. 새로 뜬 주소를 다시 공유하면 된다.
  - `allowedHosts` 는 `.trycloudflare.com` 전체를 허용해 두었으므로 주소가 바뀌어도 config 재수정은 필요 없다.
- **`http://127.0.0.1:8000/api/health` 가 안 뜬다.**
  - 백엔드(1단계)가 안 켜졌거나 8000 포트가 다른 프로세스에 점유됨. 1단계 창의 에러 메시지를 확인한다.
- **cloudflared 명령을 못 찾는다.**
  - 전체 경로로 실행: `& "C:\Users\wzxcv\AppData\Local\Microsoft\WinGet\Packages\Cloudflare.cloudflared_Microsoft.Winget.Source_8wekyb3d8bbwe\cloudflared.exe" tunnel --url http://localhost:5173`
