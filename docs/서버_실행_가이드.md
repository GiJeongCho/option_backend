# 서버 실행 가이드 V2

> 최종 업데이트: 2026-10-23  
> 목적: 컴퓨터가 꺼졌다 켜진 뒤 옵션 웹을 다시 운영하는 순서

## 1. 운영 구성 구분

### 최종 외부 운영

- 화면: GitHub Pages의 `https://netbitex.com/option/`
- API: 현재 PC의 FastAPI `127.0.0.1:8713`
- 외부 API: `https://api.netbitex.com`
- 터널: Windows 서비스 `cloudflared`

최종 배포가 끝난 뒤에는 프론트엔드가 GitHub Pages에서 실행되므로
이 PC에서 `npm run dev`를 실행할 필요가 없다. 컴퓨터가 다시 켜지면
**FastAPI 백엔드만 실행**하면 되고, `cloudflared`는 Windows
서비스로 자동 시작한다.

### 로컬 개발

- 백엔드: `127.0.0.1:8713`
- 프론트엔드: `127.0.0.1:5173`
- Vite가 로컬 `/api` 요청을 `8713`으로 프록시

화면 코드를 수정하거나 아직 GitHub Pages 배포 전이라면 백엔드와
프론트엔드 터미널을 둘 다 실행한다.

## 2. 컴퓨터를 다시 켠 뒤 실행 순서

### 1단계: 백엔드 실행

Cursor 터미널 또는 Anaconda Prompt를 연다. 프롬프트 앞에
`(base)`가 없다면 먼저 다음 명령을 실행한다.

```powershell
conda activate base
```

백엔드 실행:

```powershell
cd C:\project\option\backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8713
```

- `INFO: Application startup complete.` 가 뜨면 정상.
- 운영 중에는 `--reload`를 붙이지 않는다.
- 이 터미널은 운영하는 동안 닫지 않는다.

로컬 확인:

```powershell
Invoke-RestMethod http://127.0.0.1:8713/api/health
```

`status`가 `ok`이면 백엔드가 정상이다.

### 2단계: 프론트엔드 실행

다음 중 해당하는 경우에만 실행한다.

- 로컬에서 화면을 확인할 때
- 프론트엔드 코드를 수정할 때
- 아직 `netbitex.com/option/` 배포 전일 때

```powershell
cd C:\project\option\frontend
npm run dev
```

- `VITE vX.X.X ready` 와 `Local: http://127.0.0.1:5173/` 가 뜨면 정상.
- 로컬 개발 중에는 이 터미널도 닫지 않는다.
- 의존성이 없다는 오류가 나면 한 번만 `npm install`을 실행한다.

로컬 화면:

```text
http://127.0.0.1:5173/
http://127.0.0.1:5173/#strategy-analysis
```

GitHub Pages 배포가 완료된 운영 환경에서는 이 단계를 건너뛴다.

### 3단계: Cloudflare Tunnel 서비스 확인

새 PowerShell에서:

```powershell
Get-Service cloudflared
```

`Status`가 `Running`이면 추가 명령은 필요 없다. `Stopped`이면
관리자 PowerShell에서 다음 명령을 실행한다.

```powershell
Start-Service cloudflared
```

터널 토큰 설치 명령은 최초 연결 또는 토큰 회전 때만 사용한다.
컴퓨터를 다시 켤 때마다 토큰을 다시 입력하지 않는다.

### 4단계: 외부 주소 확인

API:

```text
https://api.netbitex.com/api/health
```

화면:

```text
https://netbitex.com/option/
https://netbitex.com/option/#strategy-analysis
```

`api.netbitex.com`에서 `502 Bad Gateway`가 나오면 대부분 FastAPI
백엔드가 꺼져 있는 경우다. 1단계부터 다시 확인한다.

## 3. 재부팅 후 최소 체크리스트

최종 운영:

1. 백엔드 터미널 실행
2. 로컬 `/api/health` 확인
3. `cloudflared`가 `Running`인지 확인
4. 외부 `api.netbitex.com/api/health` 확인
5. `netbitex.com/option/` 확인

로컬 개발:

1. 백엔드 터미널 실행
2. 프론트엔드 `npm run dev` 실행
3. `127.0.0.1:5173` 확인

## 4. 정상 종료

- 백엔드 터미널에서 `Ctrl + C`
- 로컬 개발 중이면 프론트엔드 터미널에서도 `Ctrl + C`
- `cloudflared` Windows 서비스는 계속 두어도 된다.

컴퓨터를 종료하면 API는 중단되고 GitHub Pages 화면만 남는다.
컴퓨터를 다시 켠 뒤 백엔드를 실행하면 데이터 조회와 백테스트가
복구된다.

## 부록 A. 임시 `trycloudflare.com` 공유 방식

이 방식은 GitHub Pages와 `api.netbitex.com` 고정 주소를 사용하기
전의 임시 개발 공유 방식이다. 고정 주소 배포가 완료되면 사용할
필요가 없다.

> 아래 방식에서는 터미널 3개를 모두 켜 둬야 한다.

### 1단계. 백엔드 실행 (터미널 1)

```powershell
cd C:\project\option\backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8713
```

### 2단계. 프론트엔드 실행 (터미널 2)

```powershell
cd C:\project\option\frontend
npm run dev
```

### 3단계. 임시 인터넷 터널 (터미널 3)

```powershell
cloudflared tunnel --url http://localhost:5173
```

- 실행하면 출력 중간에 아래처럼 **공개 주소**가 나온다:

  ```
  +----------------------------------------------------------+
  |  Your quick Tunnel has been created! Visit it at (it may take some time to be reachable):     |
  |  https://랜덤이름.trycloudflare.com                        |
  +----------------------------------------------------------+
  ```

- 이 `https://....trycloudflare.com` 주소를 상대에게 전달하면 접속된다.
- 이 창도 켜둔 채로 둔다.

---

### 임시 주소 접속·공유

- 상대는 3단계에서 나온 **`https://....trycloudflare.com`** 주소로 접속한다.
- `/api` 데이터도 이 주소를 통해 자동으로 동작한다 (별도 설정 불필요).

## 5. 새 옵션 원자료 추가

새 주문번호 폴더는 다음 이름 조각을 포함하면 자동으로 발견한다.

```text
[파생 옵션 코스피200 위클리]일중 매매정보(1분)
```

예를 들어 주문번호가 바뀐 새 폴더를 `backend\rowdata` 아래에 그대로
추가하면 코드에 폴더명을 다시 등록할 필요가 없다. 기존 폴더와 같은
거래일 CSV가 중복되면 어느 파일을 사용할지 임의로 선택하지 않고
오류로 중단한다.

원자료 추가 후 전체 과거 데이터와 모든 저장 전략을 다시 계산한다.

```powershell
cd C:\project\option\backend\analysis\option_5x
python refresh_all_backtests.py
```

이 명령은 데이터 프로파일, 완료된 만기 그룹, 공통 백테스트,
S1~S6 전체 저장 버전과 독립 감사를 순서대로 재생성한다. 결과가
최신 완료 만기까지 생성되지 않은 전략이 하나라도 있으면 실패한다.
원자료의 마지막 날짜에 아직 만기가 오지 않은 다음 월물은 완료
만기로 간주하지 않으므로, 원자료 최대 날짜와 전략 결과의 마지막
만기일은 다를 수 있다.

- 실행 로그: `backend\analysis\option_5x\output\refresh_logs`
- 최종 상태:
  `backend\analysis\option_5x\output\refresh_all_backtests_summary.json`
- 중간 실패 후 재개:
  `python refresh_all_backtests.py --from-step 실패한스크립트.py`
- `/api/health`의 `strategyRefreshCurrent`가 `true`면 현재 원자료
  최대 날짜까지 전략 재생성이 완료된 상태다.

재생성이 끝난 뒤 백엔드를 재시작하면 전략별 분석과 날짜 선택에
새 데이터가 반영된다.

## 6. 자주 겪는 문제

- **접속 시 403 `Blocked request. This host is not allowed.`**
  - Vite가 외부 도메인을 막은 경우다. `frontend/vite.config.ts` 의 `server.allowedHosts` 에 `'.trycloudflare.com'` 이 있는지 확인한다. (이미 설정해 둠)
  - 설정을 고쳤으면 Vite가 자동 재시작될 때까지 기다렸다가 다시 접속한다.
- **터널을 다시 켜면 주소가 매번 바뀐다.**
  - 무료 quick 터널의 특성이다. 새로 뜬 주소를 다시 공유하면 된다.
  - `allowedHosts` 는 `.trycloudflare.com` 전체를 허용해 두었으므로 주소가 바뀌어도 config 재수정은 필요 없다.
- **`http://127.0.0.1:8713/api/health` 가 안 뜬다.**
  - 백엔드(1단계)가 안 켜졌거나 8713 포트가 다른 프로세스에 점유됨. 1단계 창의 에러 메시지를 확인한다.
- **cloudflared 명령을 못 찾는다.**
  - 전체 경로로 실행: `& "C:\Users\wzxcv\AppData\Local\Microsoft\WinGet\Packages\Cloudflare.cloudflared_Microsoft.Winget.Source_8wekyb3d8bbwe\cloudflared.exe" tunnel --url http://localhost:5173`

## 7. 고정 주소 상세 가이드

quick 터널은 주소가 매번 바뀌고 업타임 보장이 없다. 항상 같은
주소가 필요하면 Cloudflare 계정의 **named tunnel**을 사용한다.

고정 주소 `api.netbitex.com` 연결과 GitHub Pages의
`netbitex.com/option/` 배포 절차는 다음 문서를 따른다.

`backend/docs/NETBITEX_옵션_외부배포_Cloudflare_Tunnel_가이드.md`

> 보안: `cloudflared service install` 명령 뒤의 `eyJ...` 값은
> 비밀 토큰이다. Markdown, 코드, Git, 채팅, 캡처 화면에 절대
> 저장하거나 공유하지 않는다. 노출된 토큰은 Cloudflare에서 즉시
> 회전한 뒤 기존 연결도 재시작한다.
