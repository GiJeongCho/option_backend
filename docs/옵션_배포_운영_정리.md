# 옵션 화면 배포·운영 정리

> 작성일: 2026-10-23
> 대상 화면: `https://netbitex.com/option/`
> 데이터 API: `https://api.netbitex.com`

이 문서는 "코드/데이터가 바뀌면 무엇을 해야 하는가"를 한 장으로 정리한 것이다.

---

## 1. 전체 구조 (중요: netbitex 주소가 2개다)

| 주소 | 역할 | 실제 위치 |
|---|---|---|
| **netbitex.com**/option/ | **화면만** (HTML/JS/CSS, 빌드된 스냅샷) | GitHub Pages — `GiJeongCho/NetbiX_homepage` 저장소 |
| **api**.netbitex.com | **데이터** (전략/백테스트 계산) | Cloudflare Tunnel → **내 PC의 FastAPI** |

- `netbitex.com` 은 "껍데기(화면)"만 준다. 데이터 계산에 전혀 관여하지 않는다.
- `api.netbitex.com` 은 Cloudflare Tunnel을 거쳐 **내 PC** 의 FastAPI(`C:\project\option\backend`)로 연결된다.

### 데이터가 흐르는 길
```
브라우저 (netbitex.com/option/ 화면)
      │  /api/... 요청
      ▼
https://api.netbitex.com          ← Cloudflare Tunnel 입구
      ▼
내 PC  http://localhost:8713      ← FastAPI (app.main)
      ▼
C:\project\option\backend  →  rowdata(코스피200 선물/현물) 로 계산 → 응답
```

- 즉 **백테스트 계산은 내 PC에서 돌아간다.** PC와 FastAPI가 켜져 있어야 데이터가 나온다.

## 2. 저장소 위치 (헷갈리지 말 것)

| 저장소 | 경로 | remote | 용도 |
|---|---|---|---|
| **사이트(배포)** | `C:\project\NetbiX_homepage` | `GiJeongCho/NetbiX_homepage` (main) | **여기서 push 해야 netbitex.com 이 바뀐다** |
| **프론트 소스** | `C:\project\option\frontend` | (없음) | 화면 코드 원본. 여기서 빌드만 함 |
| **백엔드 소스** | `C:\project\option\backend` | (없음) | FastAPI + 분석 코드 + rowdata |

- `C:\project\option` 저장소는 GitHub remote가 **없다.** 여기서 `git push` 해도 사이트는 안 바뀐다.
- 배포는 **반드시** `C:\project\NetbiX_homepage` 에서 한다.
- `netbitex.com` 도메인은 `NetbiX_homepage` 저장소에만 연결돼 있다(CNAME). 같은 도메인을 다른 저장소로 동시에 배포할 수 없다.

## 3. 무엇을 바꿨을 때 무엇을 하나

| 바꾼 것 | 해야 할 일 |
|---|---|
| **프론트 화면 코드** (`frontend\src`) | **빌드 → 복사 → push** (아래 4번) |
| **백엔드 코드** (`backend`) | FastAPI **재시작**만 (빌드·push 불필요) |
| **데이터** (분석 재실행, rowdata 갱신) | 아무것도 안 함 (백엔드가 실시간 응답) |

> 핵심 한 줄: **화면(프론트)을 고치면 반드시 다시 빌드+push 해야 반영된다.**
> 백엔드/데이터는 내 PC에서 실시간이라 그럴 필요 없다.

## 4. 프론트 화면 재배포 (3단계)

프론트 `src` 를 수정한 뒤에만 실행한다.

```powershell
# ① 빌드
cd C:\project\option\frontend
npm run build

# ② 빌드 결과를 사이트 폴더로 복사
Copy-Item -Recurse -Force C:\project\option\frontend\dist\* C:\project\NetbiX_homepage\option\

# ③ 사이트 저장소에서 커밋 & push
git -C C:\project\NetbiX_homepage add option
git -C C:\project\NetbiX_homepage commit -m "update option UI"
git -C C:\project\NetbiX_homepage push
```

- push 후 **1~2분** 뒤 `https://netbitex.com/option/` 에 반영된다.
- 코드를 안 바꿨다면 빌드 결과(파일 해시)가 동일하므로 빌드/푸시는 **헛수고**다.

## 5. 백엔드(FastAPI) 켜고 끄기

데이터(백테스트)가 나오려면 이게 켜져 있어야 한다.

**켜기**
```powershell
cd C:\project\option\backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8713
```

**끄기**: 그 터미널에서 `Ctrl + C`

**상태 확인**: `https://api.netbitex.com/api/health`
- `{"status":"ok"}` → 정상 (화면에 데이터 뜸)
- `502` → FastAPI 꺼짐 (화면은 떠도 데이터 안 옴)

> 운영 시 `--reload` 는 쓰지 않는다(개발용).

## 6. 자주 겪는 문제 (Troubleshooting)

### 화면은 뜨는데 데이터가 안 나온다 / `502`
- 원인: FastAPI가 꺼져 있음 (Cloudflare Tunnel은 살아 있음).
- 해결: 5번으로 FastAPI 실행. `api/health` 가 `ok` 인지 확인.

### `git push` 가 "master has no upstream branch" 라고 뜬다
- 원인: `C:\project\option` (프론트/백엔드 소스) 저장소에서 push함. 여긴 remote가 없음 → **엉뚱한 저장소.**
- 해결: 배포는 `C:\project\NetbiX_homepage` 에서만 한다(2·4번).

### `git push orgin` 이 안 된다
- 단순 오타. `orgin` ❌ → `origin` ⭕.

### `D:\project\NetbiX_homepage` 가 안 보인다 / "No such file or directory"
- 과거에 D 드라이브에도 사본이 있었으나, **진짜 작업 저장소는 `C:\project\NetbiX_homepage`** 다.
- D 드라이브(외장/USB)는 분리되면 접근 불가. C 경로를 사용한다.

### Git "dubious ownership" 경고
```powershell
git config --global --add safe.directory C:/project/NetbiX_homepage
```
